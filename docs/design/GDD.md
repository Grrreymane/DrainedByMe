## 1. 创作 Brief

| 要素 | 现行选择 |
| --- | --- |
| 类型 | 成年合租群像、日常相处、四晚 Gal，保留轻量补给与饥饿失败 |
| 场景 | 四位室友的共享公寓，客厅、厨房与窗边等日常空间 |
| 时间 | 先借住四晚；每晚选一个人，第四晚读完后进入唯一后记 |
| 主角 | 零 / Null，26 岁、无性别、靠 Token 维持形体的幻想生物 |
| 视角 | 第一人称有限视角；`narrator` 也是零的“我”，不窥探别人内心 |
| 目标 | 在补给足够的前提下认识室友，决定以后如何一起生活；不再赶工或推进小房间到 100 |
| 基调 | 轻松生活对白、玩笑与彼此了解；角色意愿、休息和相处边界清楚 |
| 篇幅 | 按一条实际四晚路线单独核验；不沿用旧十二轮的字数与游玩时长 |

Token 是世界内的虚构资源，来自角色自身，不经机器、终端或接口转移。普通饭菜可以成为生活话题，但不能代替规则中的 Token 补给。全员成年，现行数据写双方先说好取用范围与停止；不因用户历史稿或角色名承诺新增情色内容。

## 2. 体验支柱

1. **先选人，再相处。** 每晚公共开场后选择一人，先读个人场景和回应，再决定补给档位。
2. **来访推动个人场景。** 每人四次场景按自身已完成来访次数推进，不按日历晚数直接索引。
3. **次数与档位分别记忆。** 重访问候取决于上次找谁和是否经历贪心休息；同角色同档位再次补给使用重复文本，不重演第一次。
4. **代价事先可见。** Token、饱食结算、锁定与恢复时间均由引擎预览；贪心和致命饥饿选择需要再次确认。
5. **休息不等于永久离场。** 贪心清零只锁下一晚，隔晚恢复；白天的公共生活仍可出现该角色。

## 4. 四晚与个人场景

| 晚数 | 公共标题 | 作用 |
| --- | --- | --- |
| 1 | 今天开始借住 | 认识公寓里的生活，第一次选择相处对象 |
| 2 | 开始认得家里的声音 | 熟悉日常，承接前次补给的次日与选人可用性 |
| 3 | 今晚坐谁旁边 | 四人的邀请出现，玩家结合自己的意愿与休息安排选择 |
| 4 | 四晚之后呢 | 商量以后如何住，最后一次选择，完整读完再进入后记 |

| 角色 | 第一次来访 | 第二次来访 | 第三次来访 | 第四次来访 |
| --- | --- | --- | --- | --- |
| Codex | 厨房门口的位置 | 那间朝南的房 | 不许提前夸的试吃 | 她想有人一起逛菜场 |
| Claude | 可以问回来 | 沙发上的即兴悬疑 | 今天你来问 | 问到下个周末 |
| Cursor | 给新叶子拍张照 | 她喜欢的那扇窗 | 今晚由她来讲 | 窗边可以坐两个人 |
| WorkBuddy | 片头还没放完 | 他也会挑剔 | 轮到他挑今晚 | 下次去影院吧 |

每局只有四次选人机会，不能一次读完十六段个人场景。当天第一次找某人仍然读其第一次来访，即使已是第四晚；重访场景必须兼容未看其他角色路线的情况。

## 5. 核心循环与状态

序章 → 本晚公共开场 → 选人 → 重访问候（如有）＋个人来访 → 两项回应 → 所选回应对白 → 三档补给预览与确认 → 初次/重复补给片段 → 次日片段 → 主动进入下一晚或后记。

引擎阶段为 `select → talk → mode → result → select / ended`。读文字、查看预览、回看与打开菜单不花资源。`commit` 结算但不换晚、不立即结束，`advance` 才推进夜晚、恢复额度或设置结局。

- 全局：`version=4`，`night=1..4`，`energy=0..60`，`phase`，`selected`，`choice`，`history`，`actions`，`lastResult`，`endingId`。
- 角色：`tokens`、`cap`、`visits`、`affinity`、`blockedNight`、`resets`。初始额度等于第一晚容量，来访、亲近值与重置次数均为 0。
- 每次 `commit` 令所选角色 `visits +1`；回应 0 令 `affinity +2`，回应 1 令 `affinity +1`。回应本身不直接扣饱食或改变资源。
- 不再有十二轮、交付/小房间进度、专长、疲劳、默契、校准、重置券或中段扩容。

## 6. 补给、休息与饥饿

初始饱食 **28**，上限 **60**（吃不下的部分溢出浪费），四晚夜耗依次为 **20 / 25 / 30 / 35**。补给量为本次吸走的 Token 乘以此人的顶饱系数（WorkBuddy 为 0.5，向下取整，其余为 1）：

`feed = floor(cost × nourish)`，`energyAfter = clamp(energy + feed − drain(night), 0, 60)`

| 档位 | `cost` | 可执行条件 | 角色结算 |
| --- | --- | --- | --- |
| `shallow` 浅尝 | 10 | 剩余额度严格大于 10，且本晚未锁定 | 扣 10，不清零 |
| `deep` 深补 | 26 | 剩余额度严格大于 26，且本晚未锁定 | 扣 26，不清零 |
| `greedy` 贪心 | 当前剩余全部额度 | 剩余额度大于 0，且本晚未锁定 | Token 归零，`blockedNight = night + 1`；Codex 第一次改为全局重置，次晚回满、不休息 |

**用户确认规则：贪心清零只锁下一晚，隔晚恢复。** 从第 N 晚贪心后，进入 N+1 晚该人仍为 0、不可选；进入 N+2 晚恢复到自身容量。普通换晚恢复为 `min(cap, tokens + regen)`（Codex 0、Claude 回满、Cursor 12、WorkBuddy 20），也适用于未被贪心锁定的本晚所选角色。无真实时间倒计时，不靠等待现实时间恢复。

第三晚贪心会锁第四晚，恢复落在本局之外；第四晚贪心也有休息安排，但不会生成第五晚可玩流程。清零不表示永久消失，更不表示另外三人同时没额度。

- 结算饱食 `<=10` 提醒偏低；`<=0` 需要再次确认，可以取消。
- 贪心即使不致命也需要确认，提示具体清零与休息后果。
- 可以保留轻量饥饿失败。致命结算使用 UI 的虚弱/未获足够补给文本，读完后 `advance` 进入 `hunger`，不展示或解锁正常补给 CG。
- 饱食与角色 Token 是不同状态：某角色归零不自动导致玩家饥饿；玩家饥饿也不代表全员额度归零。

## 7. 初次、重复、次日与重返

`story.js` 提供 `supplements[id][mode]`、`repeatSupplements[id][mode]`、`morning[id][mode]`、`returnLines[id][kind]`。

- **初次/重复**：只比较更早夜晚是否已完成相同“角色＋档位”的补给；当前 `commit` 已进入历史，不能把它算成此前使用。
- **次日**：读取刚完成的 `lastResult.character` 与 `lastResult.mode`，而不是猜测下一晚选谁；饥饿由 UI 特例替换。
- **重返**：该人上次补给为贪心且已隔至少两晚，使用 `afterGreedy`；否则上次在紧邻前晚使用 `consecutive`；其他已有来访使用 `switched`；首次不插问候。
- 以上是按历史选取的静态文本，不是在线模型生成，也不是每晚全文重新生成。

Claude 用户稿已接入 `supplements.claude.deep` 首次深补；重复深补使用独立的 `repeatSupplements.claude.deep`。本轮只同步文档，不重引、改写或扩展稿件。

## 8. 六种结局

结局统一由 `advance` 设置，命中后只读一份 `endings[endingId]`。

| 优先级 | ID / 当前标题 | 精确条件 |
| --- | --- | --- |
| 1 | `hunger` / 还没说出口 | 任一晚结算饱食 `<=0`，读完结果后推进 |
| — | 继续下一晚 | 饱食 `>0` 且当前尚非第四晚 |
| 2 | `codex` / 和她一起出门 | 第四晚结束，最后所选人为 Codex，累计 `visits >=2` 且 `affinity >=3` |
| 2 | `claude` / 问题还有很多 | 同上，最后所选人为 Claude |
| 2 | `cursor` / 一起等新叶子 | 同上，最后所选人为 Cursor |
| 2 | `workbuddy` / 这次一起去影院 | 同上，最后所选人为 WorkBuddy |
| 3 | `household` / 明天也在这里 | 第四晚结束且没有满足最后所选人的个人结局条件 |

不排序比较四人亲近值；即使早先另一人的值更高，也只检查最后所选人。个人结局不要求读完该人全部四段；后记不能假定第四次邀请已经发生。`household` 是默认合住后记，不要求四人各选一次。

## 11. 架构与运行

HTML / CSS / JavaScript 离线实现，无账户、后端、模型调用或真实 Token 消费。Node.js 要求 >=20，命令统一使用 `package.json` 中的 npm scripts，不依赖某台机器的 Node 路径。

- `src/engine/core.js`：纯规则及 v4 引擎档验证，不依赖剧情、DOM、时钟、随机数或存储。
- `src/data/story.js`：UMD 四晚剧情，浏览器全局 `AfterhoursStory`。
- `src/ui/app.js`：阅读状态机、引擎调用、存读档、回看与 CG 收藏。
- `npm run dev` 本机试玩；`npm test`、`npm run build`、`npm run verify`、`npm run check`、`npm run test:e2e`、`npm run package` 沿用现有入口，适配和最终执行结果由主代理确认。

源码、合同、测试、构建脚本和素材由对应代理负责；本次文档同步不更改这些文件，也不公开发布。
