## 1. 世界、视角与人物

零 / Null 是 26 岁、无性别、靠 Token 维持形体的幻想生物，先在共享公寓借住四晚。第一人称有限视角：`narrator` 使用“我”，`player` 表示零的回应；不能叙述自己失去意识后才发生的事。

Token 来自室友自身，是虚构能量，不来自机器、插座或终端。食物香气、做饭与电影是生活主题，不会额外发放补给。全员成年，当前补给文字以双方事先说好取用范围与停止为前提，不把疲惫、休息或饥饿当作加重亲密的理由。

| 人物 | 资料与声线 | 个人场景主轴 |
| --- | --- | --- |
| Codex | 27 岁女性白狼；话短、嘴硬，愿意讲做饭失败的笑话 | 厨房门口 → 选房旧事 → 煎饼试做 → 一起逛早市 |
| Claude | 29 岁女性狐；爱追问，也愿意被问、讲糗事 | 问回来 → 即兴悬疑 → 今天你问 → 下个周末 |
| Cursor | 25 岁女性黑猫；熟悉后讲绿植与照片会起劲 | 新叶照片 → 朝南的窗 → 花市与花盆 → 窗边与同行邀请 |

角色不是构建、逻辑、上下文、运维的任务专长槽。Codex 与 Cursor 的旧事是合租选房误会，不能再插入代码回滚、署名证据或 `restored_branch`。

## 2. 现行剧情数据接口

`story.js` 通过 CommonJS、AMD 或浏览器全局 `AfterhoursStory` 导出同一份数据。当前顶层包括：

| 字段 | 内容 / 使用方 |
| --- | --- |
| `title` | 游戏名称 |
| `characters[id]` | 成年人物档案，含 `id/name/age/gender/animal/color/role/tagline/bio/art` |
| `intro` | 序章对白数组 |
| `nights[0..3]` | 每晚 `title` 与 `common` 公共对白 |
| `routes[id][0..3]` | 按该角色个人来访次数排列的 `title/lines/choices` |
| `choices[0..1]` | 每段两个 `label` 与 `reply`，没有旧 `effect` 或资源脚本 |
| `supplements[id][mode]` | 同角色同档位首次补给正文 |
| `repeatSupplements[id][mode]` | 相同组合再次补给正文 |
| `morning[id][mode]` | 刚结束的补给所对应的次日片段 |
| `returnLines[id][kind]` | `consecutive/afterGreedy/switched` 三类重访问候 |
| `endings[id]` | `title/subtitle/lines`，六项互斥后记 |
| `cgMap[id][mode]` | `{id}_{mode}` 事件图键 |
| `sources` | 当前为空数组；不据此编造已查来源 |

对白行结构为 `{ speaker, text }`。角色 ID 为 `codex/claude/cursor/workbuddy`；档位为 `shallow/deep/greedy`。UI 启动会检查四晚、各人来访段落（v4 为 Codex/Claude 各四、Cursor/WorkBuddy 各二）、每次两项回应、各补给组、三类重返及六结局，不以旧十二轮数据冒充四晚内容。

## 3. 一晚的编排

序章（仅开局）→ 本晚公共段 → 选人 → 重访问候＋个人段 → 回应选项 → 所选回应正文 → 补给档位 → 补给正文 → 次日片段 → 玩家主动进入下一晚 / 后记。

四晚公共标题依次为“今天开始借住”“开始认得家里的声音”“今晚坐谁旁边”“四晚之后呢”。公共段不指定当晚相处对象，不消耗 Token，也不保证全部角色本晚可选。

### 个人次数，不是晚数

- 选人后、补给前，UI 读取 `routes[selected][characters[selected].visits]`。
- 只有 `commit` 增加该人的 `visits`；`select` 和 `choose` 不增加。
- 第四晚第一次找 Claude，仍读她的第一次场景，不跳到第四次邀约。
- Codex、Claude 各准备四段，Cursor、WorkBuddy 各两段，但每局总共只选人四次；不能把全部分支字数相加当作一次阅读量。
- 每段只播放被选中的一个 `reply`。回应 0/1 的亲近值差异由 core 在补给结算时处理，剧情不自行加值。

### 初次与重复补给

UI 在已经含本次 `commit` 的 `history` 中，只检查 `entry.night < lastResult.night` 的早先记录。此前出现过同一 `character + mode` 才读 `repeatSupplements`，否则读 `supplements`。

不能把“第二次见此人”直接等同于“重复同档位”；第二次见她第一次选深补，仍读深补初次。重复段承认双方熟悉，但不增加未实现的赠礼、额外补给或新结局旗标。

### 动态次日与重返

次日用 `morning[lastResult.character][lastResult.mode]`；这是对刚结束那晚的回响，不是下一晚角色的预言。三类问候只在曾找过此人时插入，优先级为：

1. 最近一次找此人选了贪心，且当前晚数至少为那晚加二：`afterGreedy`。
2. 否则最近一次正是前一晚：`consecutive`。
3. 否则：`switched`。

首次无重访问候。`afterGreedy` 是已经过休息晚后重返，不能写成本晚继续取用仍被锁的人。公共日常可以让休息者白天打招呼，但不能擅自解除当晚补给锁定。

## 4. 资源对白与失败连续性

- 只保留浅尝 10、深补 26、贪心全部余量三档；固定档位要求余量严格大于消耗，只有贪心能清零。
- 饱食初始 28、上限 60，吃不下的溢出浪费；零一晚比一晚饿，夜耗 20 → 25 → 30 → 35。各人额度按人设：Codex 90、每晚不回，第一次被吸空有一次全局重置、次晚回满；Claude 30 → 38 → 46 → 54、每晚回满；Cursor 55、每晚回 12；WorkBuddy 110、每晚回 20，便宜大碗但只顶一半饱。Cursor 与 WorkBuddy 要等 Codex、Claude 都被吸空过一次才出现，此前的文字不能让零去找他们。不要再写统一恢复 12、重置券、校准、专长或房间进度。
- **清零只锁紧接着的一晚，隔晚恢复满额**（Codex 第一次除外，走全局重置）。第一晚清零后第二晚休息、第三晚可再次约；第三或第四晚产生的更后续恢复只是故事外安排，不增加可玩晚数。
- 深补不会把角色扣至零，也不会自动锁下一晚。它可以写想歇会儿，但不能承诺“下一晚不可选”。
- 贪心清零与玩家饥饿是不同条件；不能把饥饿说成所有人都已经耗尽。
- `energyAfter <=0` 时 UI 不用正常 `supplements` 与 `morning`，改播自身的虚弱片段；随后 `advance` 进入 `hunger`，也不解锁正常事件图。
- 第四晚仍读补给、次日，再进入唯一结局；不能跳过结果或提前结束。

## 5. 六结局的叙事前提

| ID | 标题 | 可以依赖的条件 |
| --- | --- | --- |
| `hunger` | 还没说出口 | 补给没有抵过消耗，零的饱食归零；不保证他人额度耗尽 |
| `household` | 明天也在这里 | 活过第四晚，但最后所选人未满足个人条件；不是全员各访一次奖励 |
| `codex` | 和她一起出门 | 最后一晚找 Codex，她的 `visits >=2`、`affinity >=3` |
| `claude` | 问题还有很多 | 同上，所选人为 Claude |
| `cursor` | 一起等新叶子 | 同上，所选人为 Cursor |
| `workbuddy` | 这次一起去影院 | 同上，所选人为 WorkBuddy |

core 先检查饥饿，存活且还没到第四晚则继续；第四晚仅检查**最后所选人**，不对四人排序争最高亲近值。个人后记不能要求玩家已读第三、第四次个人场景；邀请可在后记自然首次提出。六份结局互斥，不把其他人的私人结局接在后面。
