# 完蛋，我被 Agent 包围了

**DrainedByMe** · Four nights, four AI agents, one Token-starved tentacle. An offline visual novel.

**TOKEN / AFTERHOURS** · v0.3.0 · 四晚离线 Gal / 视觉小说

你是零，一团没有性别、靠 Token 活着的成年触手怪，对 Token 有很深的欲望，没有就活不下去。你借住进 Codex、Claude、Cursor 与 WorkBuddy 的合租房四晚：刚升级 Astra、一天烧完一周额度的 Codex，审美极好、额度少但风评刚反转的 Claude，存在感很低、被 Codex 记着私仇的 Cursor，和最先把你捡回家、却被你忘掉的 WorkBuddy。每晚找一个人，聊完再决定吸多少。

## 从哪里试玩

**查看当前源码版**：需要 Node.js >=20，在项目根目录运行：

```sh
npm run dev
```

浏览器打开 `http://127.0.0.1:4173/`，进入根目录 `index.html`，点击“开始游戏”。不需要先构建；服务仅监听本机，Ctrl+C 停止。

**单文件离线版**：最终构建后直接用现代浏览器打开 `outputs/token-afterhours.html`，不需要另带素材目录。v0.3.0 美术与 UI 已完成并审看；最终重跑与打包结果以 `outputs/browser-qa.json`、`outputs/verification.json`、`outputs/visual-v8-qa.json` 与 `outputs/token-afterhours-source.zip` 为准。游戏无账户、无在线模型请求、无真实 Token 扣费。

## v0.3.0 有什么

- 界面恢复初版的米白纸面、红棕强调与“左名册 / 中央场景对白 / 右决策栏”结构；只保留四晚、饱食、Token 和当前选择所需信息，不恢复旧十二回合的任务、交付、疲劳或默契面板。
- 封面主视觉由 LightAI 依据已确认的角色母版和用户提供的构图参考生成，采用粉红花卉线、左侧标题留白与右侧四人群像；真实标题由 HTML 叠加。游戏内场景和对白为上下连体卡，不覆盖 CG。
- “纯看画面 / 恢复对白”会同步隐藏名册、上下文和对白面板，但不改变剧情状态、阅读位置或花费；隐藏时 Space / Enter 不会跳读。
- 控件最小 48×48 CSS 像素；使用本地系统字体，支持窄屏重排、200% 字号和减弱动效，不加载远程字体。
- 保留完整四晚、浅尝 / 深补 / 贪心三档和六种结局；Codex、Claude 各四次个人来访，Cursor、WorkBuddy 各两次，另有初次与重复补给、次日片段、前一晚选人引起的开场反应和重访问候。
- 逐句阅读、两项回应、已读回看、自动存档、三个手动档、当前局 JSON 导入导出和十二张事件图收藏。
- 四张立绘均以 `outputs/portraits-base-style-fixed.png` 为共同母版重新逐张生成，经 `BiRefNet-HR-matting` 去背景后制成 1120×1680 RGBA WebP；兽耳角色无额外人耳，WorkBuddy 保留短胡。十二张独立事件 CG、一张新客厅和一张独立封面均为 2560×1440；其中十一张事件 CG 于 2026-09-27 按新剧情重画（visual-v8），`claude_deep` 保留用户原稿场景。共十八项运行时资产；源尺寸与处理记录见 `docs/design/art-log.md`。

四位室友均为成年人，视觉设定为人脸加兽耳、尾，不全兽化。Claude 的首次深补场景已采用用户提供的文稿。

阅读工具有回看、跳过已读和按句子长短翻页的自动播放；后记里可以回到本局任一晚重选。没有音频播放、配音、文字速度设置或 Live2D。剧情里提及音乐与电影不代表实现了播放器；Token 与关系数值也不代表真实产品能力。

## 四晚怎么玩

1. 读本晚开场，选择一位可用室友。
2. 读来访对白，二选一回应，再选择补给；先看消耗、补给量、结算后饱食和休息提示。
3. 读完补给与次日片段，点击进入下一晚；第四晚同样读完后才进入后记。

初始饱食 **28**，饱食上限 **60**，吃不下的部分溢出浪费；零一晚比一晚饿，四晚夜耗依次为 **20 → 25 → 30 → 35**。浅尝消耗 **10 Token**，深补 **26 Token**，两档都必须留下正额度；贪心吸光对方当前全部 Token，要对方点头，被吸空的人下一晚休息。第一晚贪心 Codex 也只能把饱食填到 60（溢出 38），后面三晚仍要继续进食。Codex 额度 90、没有五小时窗口、每晚不回，第一次被吸空时官方发一次全局重置、次晚回满，只有这一次；Claude 额度少但每晚回满，上限 30 → 38 → 46 → 54 逐晚增加。Codex 和 Claude 都被吸空过一次后，零才会想起 Cursor（额度 55、每晚回 12）和 WorkBuddy（额度 110、每晚回 20，便宜大碗，但吸到的 Token 只顶一半饱，向下取整）。前一晚找了谁，第二晚其他人会有反应。饱食归零会进入轻量饥饿结局，危险选择可取消。

六结局为饥饿、继续合住与四人个人后记；完整数值、恢复规则和结局条件见 [架构与规则](docs/ARCHITECTURE.md)。个人来访按各人的访问次数推进，一局不等于读完所有人的四段。

## 操作与存档

| 输入 | 功能 |
| --- | --- |
| 鼠标 / 触屏 | 推进对白、选人、回应、补给与菜单 |
| Space / Enter / → | 推进可读对白，一晚读完时进入下一晚；控件有焦点时保留原生激活，不重复推进；纯看画面时不跳读 |
| 数字键 1–4 | 选人、回应、补给时直接选择；贪心和危险补给仍会再确认 |
| Esc | 关闭弹窗；无弹窗且焦点不在交互控件时打开存档 |
| 纯看画面 / 恢复对白 | 隐藏或恢复舞台面板，不消费 Token，不改变已读进度 |

- **存档升级为 v4**：数值规则改变（饱食上限、逐晚夜耗、WorkBuddy 半饱），引擎格式为 `four-nights-v4`，v1、v2、v3 旧存档不兼容、不迁移、不覆盖，UI namespace 为 `token-four-nights-v4`。图片收藏与规则无关，首次进入 v4 时会只读沿用 v3 已解锁的收藏。
- 每次推进自动保存；三个手动档覆盖前需确认。新局保留手动档和收藏。
- 导出只包含**当前局及阅读位置**，不含其他槽位或全收藏；导入上限 128 KiB，坏档不会替换当前局。
- 正常事件图实际载入并可见才收藏；缺图人物代示、饥饿片段和只导入结局档不补齐收藏。
- 不同浏览器、文件位置、`file://` 与本地 HTTP 不保证共享存档，换入口前请导出。禁止浏览器存储时仍可游玩与导出，但记录可能无法持久保存。
